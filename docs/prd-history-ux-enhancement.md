# PRD: 历史页交互体验升级

**日期**: 2026-05-14
**状态**: ready-for-agent
**关联**: 情绪日记 History 页面 UX 增强

---

## Problem Statement

作为情绪日记的用户，我在历史页面浏览过去的日程记录时，当前的体验过于"静态"——切换月份是瞬间跳变，日历格子虽然有情绪色但缺乏生命力，点击日期后日程列表一次性全部出现。整个页面像一个数据报表，而不是一个让我回味过往情绪的"记忆空间"。

用户进入历史页的核心意图是 **回顾和感受**，而当前页面只完成了"展示"功能，缺少"让数据有温度"的交互层。

## Solution

为历史页注入四层"安静陪伴"式的交互增强，让用户在浏览过往时感受到数据的生命力，同时保持不打扰、不喧闹的调性：

1. **月份横滑过渡** — 切换月份时，日历平滑横移，像翻阅相册一样自然
2. **日历情绪呼吸灯** — 有数据的日期格子带有微弱的呼吸脉冲，暗示"这些日子有记忆在安静地存在"
3. **日程错序入场** — 点击某天后，日程卡片以微小时序差逐个浮现，像慢慢展开一天的回忆
4. **月度情绪渐变色带** — 日历底部新增一条极淡的情绪渐变色带，从月初色延伸到月末色，一眼感知整月情绪走向

所有动效遵循 **"安静陪伴"** 设计基调：柔和缓出（400-800ms）、淡入呼吸、尊重 `prefers-reduced-motion`。配色严格使用 Seven Sense 品牌情绪色板，不引入新颜色。

## User Stories

### 月份横滑过渡
1. 作为一个经常回顾不同月份的用户，我希望点击"上一月/下一月"时日历能平滑滑入，让我感受到时间的连续性，而不是突兀的跳变
2. 作为一个对动画敏感的用户，当我启用了系统的"减少动效"设置时，我希望日历切换降级为即时切换，不影响我的浏览效率

### 日历情绪呼吸灯
3. 作为一个在日历中寻找"哪些日子值得回顾"的用户，我希望有记录的日子能通过微弱的呼吸效果吸引我的注意，而不是需要一个个仔细看色块
4. 作为一个在深夜模式下使用应用的用户，我希望呼吸灯在暗色背景下依然可见且有质感，像夜光一样柔和
5. 作为一个月有 20+ 天都有记录的高频用户，我希望呼吸灯效果足够微弱，不会因为格子太多而让整个页面显得花哨和混乱

### 日程错序入场
6. 作为一个点击日历日期查看当天日程的用户，我希望日程卡片不是一次性全部弹出，而是像展开一张折叠的信纸一样有条理地出现，给我一种"在翻阅一天"的仪式感
7. 作为一个某天记录了 10+ 条日程的用户，我不希望因为动画太长而浪费时间等待——多条日程时动画应该自动加速收束

### 月度情绪渐变色带
8. 作为一个关注长期情绪趋势的用户，我希望在日历上一眼就能感知这个月的情绪是从低走高、从高走低还是平稳，而不需要进入分析页查看图表
9. 作为一个当月没有任何记录的新用户，我不希望看到一条无意义的空白色带——它应该在我有数据时才安静出现

## Implementation Decisions

### 设计基调
- **"安静陪伴"** 为统一动效语言：淡入、呼吸、柔滑，避免弹跳、翻转、粒子等活泼效果
- 所有动画使用纯 CSS（`@keyframes` + `transition`），不引入任何第三方动画库
- 配色严格遵守 Seven Sense 品牌情绪色板：`#d75772`(-3) → `#f5867b`(-2) → `#fea979`(-1) → `#ffe062`(0) → `#3cdfe9`(+1) → `#12b8ec`(+2) → `#1686ee`(+3)
- 所有动效均需 `@media (prefers-reduced-motion: reduce)` 降级

### 模块划分

**M1 — MonthSlideTransition**（月份横滑过渡）
- 职责：封装月份切换的方向感知与滑入/滑出动画
- 接口：接收 `direction: 'prev' | 'next'` 和子内容，根据方向决定 `translateX` 方向（上一月从右滑入，下一月从左滑入）
- 技术：CSS `transform: translateX` + `opacity` transition，缓动曲线 `cubic-bezier(0.4, 0, 0.2, 1)`，时长 400ms
- 过渡逻辑：旧月滑出 + 新月滑入同时进行，过渡完成后由父组件更换实际内容
- 依赖：`HistoryPage.tsx` 中的月份状态管理（`currentYear`、`currentMonth`）

**M2 — CalendarBreathingCell**（日历情绪呼吸灯）
- 职责：为带有情绪数据的日历格子添加极弱呼吸脉冲动画
- 技术：纯 CSS `@keyframes breathe`，opacity 在 0.25 ↔ 0.35 之间，周期 2.5s，`ease-in-out`
- 作用范围：仅在 `.calendar-day.has-data` 的元素上生效
- 暗色模式适配：opacity 范围调整为 0.28 ↔ 0.38（暗色背景下需略高以保持可见性）
- 亮色模式下同一范围（0.25 ↔ 0.35）
- 扩展 `History.css` 中现有的 `.calendar-day.has-data` 规则

**M3 — ScheduleStaggeredList**（日程错序入场）
- 职责：接收日程列表数据，以错序延迟逐条渲染入场动画
- 接口：接收 `items: ScheduleItem[]` 和渲染函数 `renderItem`
- 规则：前 6 条设置递增 `animation-delay`（0ms, 50ms, 100ms, 150ms, 200ms, 250ms），第 7 条起的 `delay` 全部为 250ms（不再增长）
- 入场动画：`@keyframes scheduleSlideIn` — `translateY(12px)` → `translateY(0)` + `opacity: 0` → `opacity: 1`，时长 300ms，`ease-out`，初始 `animation-fill-mode: backwards`
- 日期切换时重新触发：通过 React `key` 绑定到当前选中日期，确保每次日期变化时动画重新播放

**M4 — MonthlyMoodGradient**（月度情绪渐变色带）
- 职责：根据该月每日情绪数据渲染一条极淡的情绪渐变色带
- 接口：接收 `dailyMoods: (number | null)[]`（长度为当月天数，null 表示无数据）和 `daysInMonth: number`
- 渲染：CSS `linear-gradient(to right, ...)`，每个有天数的日期插入对应情绪颜色停靠点，无数据日期使用 `transparent` 跳过
- 视觉：高度 3px，位于日历网格底部，`opacity: 0.6`，无数据时返回 `null` 完全隐藏
- 数据来源：使用现有 `ANALYSIS_API.monthly` 接口返回的 `dailyTotals`（已在 History 页加载）

### 现有文件修改
- **HistoryPage.tsx**：集成 M1/M3/M4，管理月份过渡状态和方向感知
- **HistoryPage.css**：新增所有 `@keyframes`、过渡样式、色带样式

### 架构约束
- 遵循前端公约：CSS Modules 用于组件级样式，不引入 Tailwind 或 CSS-in-JS
- M1 拆分为独立 `MonthSlideTransition` 组件（`components/` 目录），M3/M4 可内联在 History 页或独立拆出
- M2 为纯 CSS 改动，不创建新组件
- 使用现有 `useFetch` hook 获取月度分析数据（已在 History 页使用）
- 不新增 API 端点——M4 复用现有 `ANALYSIS_API.monthly`

### 交互细节
- 日历切换：用户点击 `<` `>` 按钮或选择年月下拉时触发 M1 横滑
- 呼吸灯：页面加载/月份切换后自动播放，无限循环
- 错序入场：用户点击日历任一天时触发 M3，切换日期时重新触发
- 色带：随月度分析数据加载完成后自动渲染，静默存在无需交互
- `prefers-reduced-motion`：所有四层动效在此媒体查询内禁用（呼吸灯→静态色块、横滑→即时切换、错序→同时出现）

## Testing Decisions

- **测试策略**：本项目前端暂无测试基础设施（无 Vitest/Jest/Playwright），本次迭代不引入测试框架
- **验证方式**：手动验证——在开发环境中逐项检查四个模块的视觉效果和交互行为
- **验证清单**：
  1. 月份横滑：上一月（←）和新一月（→）切换方向是否正确，动画是否流畅
  2. 呼吸灯：有数据/无数据格子是否区分，暗色模式下效果是否可感知
  3. 错序入场：前 6 条是否有明显时序感，7+ 条时是否不拖沓
  4. 色带：有数据月份显示、无数据月份隐藏，颜色过渡是否平滑
  5. reduced-motion：开启系统减少动效后，所有动画是否降级为即时呈现

## Out of Scope

- **Analysis 分析页 UX 增强**（渐进式揭示、图表动画过渡、AI打字机效果、情绪色调背景）——将作为独立 PRD 后续推进
- **移动端适配**——当前交互设计基于桌面端，移动端触摸手势（如滑动切月）不在本 PRD 范围
- **音频氛围层**——Analysis 页的情绪氛围音效设计不在本 PRD 范围
- **3D 翻页效果**——讨论中评估过但被否决，采用更安静的横滑方案
- **年度回顾仪式**——全屏年度情绪回顾动画不在本 PRD 范围
- **日历无限滚动**——方案B中的交互增强不在本 PRD 范围
